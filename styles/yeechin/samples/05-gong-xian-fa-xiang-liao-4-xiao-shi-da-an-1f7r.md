# 按位数统计贡献

> Problem: [3871. 统计范围内的逗号 II](https://leetcode.cn/problems/count-commas-in-range-ii/description/)

# 思路

> 你选用何种方法解题？

## 数学观察 + 按层计数

这题我按"位数分段"硬算了 4 个小时，草稿纸写满两页，公式越推越长，最后发现路走死了。换了个数法之后，代码才 6 行。这篇题解主要想把那条死路也记下来，给同样第一直觉是分段的朋友避个坑。

# 解题过程

> 这些方法具体怎么运用？

## 第一步：先看我走死的那条路

逗号个数和位数挂钩，很自然想到分段：

4~6 位数，每个 1 个逗号；

7~9 位数，每个 2 个逗号；

……

写下来就是 (10⁶-1)-(10³-1) + [(10⁹-1)-(10⁶-1)]×2 + ...，每多一段就要把前面所有段重新加一遍，根本写不出通项。即使写了前几个分段的公式能够通过测试用例也没用，因为测试用例的数位很小，给你写个十几二十位你不炸了。

## 第二步：换个维度数（顿悟）​

卡住之后突然意识到一件事：

> 这题不是统计"哪些数字有几个逗号"，而是统计"第几个逗号分别出现了多少次"。

- 第一个逗号：出现在所有 ≥ 1,000 的数里；

- 第二个逗号：出现在所有 ≥ 1,000,000 的数里（这些数量都有第1个逗号）；

- 第 k 个逗号：出现在所有 ≥ 1000ᵏ 的数里（这些书都有第k-1个逗号）。

每个达标的数贡献且只贡献一个"第 k 位逗号"，层与层之间互不嵌套（即有多个逗号的数在第一层循环就把4位数及以上的第一个逗号全算了一遍）。以 n = 1,234,567 为例：

- 第 1 层（门槛 10³）：1,233,568 个数达标 （1,000-1,233,568）→ +1,233,568

- 第 2 层（门槛 10⁶）：  234,568 个数达标（1,000,000-1,233,568） → +234,568

- 第 3 层（门槛 10⁹）：n 不够，结束

## 第三步：翻译成代码

门槛每乘一次 1000 就是下一层（注意不要separator \*= separator!!!，别问我为什么知道），达标个数 = n - 门槛 + 1，循环加到 n 不够门槛为止。

# 复杂度

- 时间复杂度: $O(logN)$
- 空间复杂度: $O(1)$
- 代码复杂度：6行。想到这道题想了4个钟就很难绷，心情复杂。

# Code

```python3
class Solution:
    def countCommas(self, n: int) -> int:
        comma = 0
        separator = 1000

        while n >= separator:
            comma += n - separator + 1
            separator *= 1000

        return comma
```

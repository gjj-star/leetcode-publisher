# 按区间统计贡献

> Problem: [3871. 统计范围内的逗号 II](https://leetcode.cn/problems/count-commas-in-range-ii/description/)

# 思路

> 按区间统计贡献

观察一下标准格式：

- 1~999：没有逗号（0 个）

- 1000~999999：每个数 1 个逗号

- 1000000~999999999：每个数 2 个逗号

- 以此类推

所以每个区间里的数字，逗号数量是一模一样的。那这一段的逗号总数就是：

> `区间长度 × 该区间每个数的逗号数`

不用管数字之间怎么互相叠加，每段独立算完加进总数就行。

# 解题过程

## 第一步：确定每个区间的左右边界

左边界就是从 1000 开始，每次乘 1000：

```
left = 1000 → 1000000 → 1000000000 → ...
```

右边界是这个区间的最大值（比如 1000 这一段的右边界是 999999），但如果 n 还没到区间末尾，就取 n：

```python3
right = min(n, left * 1000 - 1)
```

### 第二步：区间长度 × 逗号数

区间长度是 right - left + 1，每段对应的逗号数就是循环次数 count（从 1 开始，每升一段 +1）：

```python3
comma += (right - left + 1) * count
```

## 第三步：循环到 n 装不下为止

left 一路乘 1000 往上走，一旦超过 n 就停（说明后面的区间根本不存在）。

# 复杂度

- 时间复杂度: $O(logN)$
- 空间复杂度: $O(1)$
- 代码复杂度：7行

# Code

```python3
class Solution:
    def countCommas(self, n: int) -> int:
        comma = 0
        left = 1000
        count = 1

        while n >= left:
            right = min(n , left * 1000 - 1)
            comma = comma + (right - left + 1) * count
            left *= 1000
            count += 1
        
        return comma
```

> PS：这版本其实是我第一版想走的路——按区间分段。当时死在了"每段要把前面所有段重新加一遍"，公式越推越长；现在换个写法，每段只算自己那部分、互不叠加，反而清爽了。同一题目，换个组织方式就是天壤之别。而且也是最符合人类宝宝的思路，按位数贡献的算法没学过真想不出来。

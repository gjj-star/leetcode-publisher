# 题解文风档案

基于 7 篇样例自动归纳。生成新题解时请严格对齐下面的骨架、节奏和口吻。

来源：leetcode 用户 yeechin

## 一、章节骨架

按此顺序，用一级标题：

- `# 思路`　（7/7 篇都有）
- `# 解题过程`　（7/7 篇都有）
- `# 复杂度`　（7/7 篇都有）
- `# Code`　（7/7 篇都有）

正文第一行固定是 `> Problem: [题号. 题名](题目链接)`（7/7 篇）。

## 二、开头怎么写

`# 思路` 下面紧跟一句引用块，一句话点明方法，例如：

> 动态规划：$dp[n][k]$ 表示前 $n$ 个点里选 $k$ 条不重叠线段的方案数，转移里那串连续求和用前缀和 $pre$ 维护
> 贪心
> 二维降一维（投影 + 区间求交）
> 按区间统计贡献

## 三、解题过程

用 `## 第N步：<小标题>` 分步（7/7 篇采用）。实际标题样例：

- `## 第一步：暴力为什么写不出来`
- `## 第二步：真正决定未来的只有两个数`
- `## 第三步：转移看最后一个点`
- `## 第四步：那串求和交给前缀和`
- `## 第五步：滚动数组降维`
- `## 第二步：贪心到底按什么排`

踩过的坑单独成节，标题里带「坑」字，样例：

- `### **第一步：先被两个坑各踹一脚**`
- `### **坑 1：长度是"至少 k"，不是"正好 k"**`
- `### 坑 2：我算成了"所有回文串的数量"`
- `### 第三步：踩了个坑，== 改 <=`

## 四、篇幅与密度

- 正文字数：中位数 **1477**（区间 1238–3219）
- 代码块：平均 2.4 个/篇，语言以 `python3`、`typescript` 为主
- 行内公式 `$...$`：平均 8.7 处/篇
- 块级公式：平均 0.9 处/篇
- 无序列表：平均 6.6 条/篇
- 加粗强调：平均 3.4 处/篇
- 表格：平均 0 行/篇（该风格不用表格）

## 五、口吻

以第一人称叙述推导过程，允许暴露自己走过的弯路。实测特征词频（每篇）：

- 第一人称「我」：3.1 次
- “我一开始 / 最开始”：0.3 次
- “其实 / 说白了”：0.3 次
- “才发现 / 后来发现”：0.6 次
- 口语词：1.1 次
- 自嘲：0.7 次

要的是「一个人在自己讲怎么想通的」，不是「教科书在陈述定理」。

## 六、反面清单

- 不要把思路写成流水账，`# 思路` 只留一句话结论。
- 不要堆砌没有推导过程的代码。
- 不要用「我们」「读者」这类教科书人称。
- 不要用表格罗列复杂度，这个风格用无序列表。
